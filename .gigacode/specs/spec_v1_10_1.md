## 📋 Требования

### TR-81. Ошибка хранилища при старте доходит до игрока

- Сообщение, опубликованное в шину **до появления первого подписчика**, доставляется
  первому подписчику в порядке публикации ровно один раз; после доставки очередь пуста.
- Повторная подписка (в том числе в `StrictMode`) не показывает уже доставленные сообщения.
- Дедупликация 1.10.0 сохраняется: одна и та же пара «действие + сообщение» не публикуется
  повторно, пока не было успешной записи.
- Сценарии при старте:
  - повреждённая запись → модалка «Ошибка хранилища» с текстом «Данные повреждены. Счёт сброшен.»,
    счёт 0, карта открывается, раунд играется;
  - недоступное хранилище → модалка с текстом «Хранилище недоступно. Игра работает без сохранения.»,
    игра идёт в режиме «память вместо диска»;
  - очередь не является глобальным состоянием: она живёт в экземпляре шины (A78).
- Проверка — App-тест: `StatsService` на репозитории, который бросает на первом `load()`,
  **без** ручного `errors.report(...)`.

### TR-82. Слой `data` не зависит от `app`

- `src/data/**` не импортирует `src/app/**` — ни значения, ни типы.
- Порт и текст заголовка живут в `core`: `ErrorReporter { report(title, message): void }`
  и `STORAGE_ERROR_TITLE = 'Ошибка хранилища'` (`src/core/error-reporting.ts`).
- `StatsService` принимает `ErrorReporter | null`; `ErrorBus` реализует порт; `App` и тесты
  работают с шиной через порт.
- Граф слоёв: `core ← data ← services ← app`; циклов на уровне файлов и слоёв нет.
- Проверка: `grep -RIn "from '../app" src/data` — пусто; тесты и сборка зелёные.

### TR-83. Подтверждение выхода — кастомная модалка

- Клик ✕ во время раунда **не** завершает раунд, не пишет статистику и не двигает позицию:
  открывается модалка `.modal-overlay.open` в существующих классах.
- Тексты фиксированы: заголовок «Выйти из игры?», сообщение «Заработано N очков сгорят.»,
  кнопки «Выйти» (`btn-primary`) и «Остаться» (`btn-secondary`).
- «Выйти» → тот же путь, что «На карту» (TR-85), плюс откат позиции без сохранения;
  «Остаться» и клик по оверлею закрывают модалку, раунд продолжается без потери состояния.
- Повторный клик ✕ при открытой модалке — no-op; вторая модалка не появляется.
- `alert()` / `confirm()` / `prompt()` в `src/**` отсутствуют; нативные диалоги не
  подменяются в тестах.
- Проверки: модалка появляется, «Остаться» не меняет счёт/позицию, «Выйти» возвращает на
  карту, `grep` пуст.

### TR-84. Миграция сохраняется, лог пишется один раз

- После успешной миграции запись сохраняется в хранилище (write-back) с текущей версией
  `CONFIG.VERSION`; повторный `load()` не выполняет миграцию и ничего не пишет.
- Лог — одна строка на фактически выполненную ступень, формат прежний:
  `console.info('[StatsSchema] миграция', N, '→', N+1)`.
- Если write-back не удался: применяется действие `handleError`, игрок видит сообщение,
  игра продолжается; в пределах экземпляра сервиса ступень больше не логируется.
- Загрузка актуальной записи (version = `CONFIG.VERSION`) не пишет ни в хранилище, ни в консоль.
- Тестовый двойник `MemoryRepository` сериализует данные (глубокая копия), как
  `LocalStorageRepository`; сьют двойника обновляется под это поведение.
- Проверки: сериализующий репозиторий с записью v1 — три `load()` дают **две** строки
  лога, повторный `load()` после write-back — **ноль**; тест на `migrate()` сохраняется.

### TR-85. Единый путь возврата на карту

- В `App` один обработчик `returnToMap()`: сначала чтение статистики, затем `navigate('map')`.
- ✕ (после `exitGame()`), «На карту» и смена карты используют **его же**; отдельных копий
  пары «reload + navigate» нет.
- Счёт на карте включает завершённый раунд на всех путях: «Играть снова» → ✕, «На карту»,
  смена карты, F5.
- Проверки: существующий сьют `App.map-freshness` расширяется путём смены карты.

### TR-86. Провал записи позиции откатывает отображение

- Результат `saveTrainerIndex()` проверяется.
- При провале записи отображаемый индекс остаётся прежним (до раунда), позиция в памяти
  не фиксируется, счёт раунда (если записан) отображается, сообщение об ошибке приходит
  через шину (A79).
- При успешной записи поведение 1.10.0 сохраняется: победа закрепляет позицию, провал на
  новом откатывает, повторная игра позицию не пишет.
- Проверка: репозиторий бросает на `save` → `--current` остаётся на прежнем тренажёре,
  счёт не «прыгает».
