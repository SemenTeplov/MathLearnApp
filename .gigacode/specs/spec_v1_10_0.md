## 📋 Требования

### TR-71. Игровые ошибки хранилища доходят до игрока

- Классификация ошибки остаётся за `handleError()`; действие выполняет вызывающий (A11).
- Возвращённый `ErrorInfo.userMessage` **обязан** показываться игроку существующей
  модалкой ошибок (`.modal-overlay.open`), один раз на ошибку, без `alert()`/`confirm()`.
- Действия применяются, а не только возвращаются:
  - `reset` — повреждённая запись очищается, счёт начинается с 0, игрок видит сообщение;
  - `memory` — приложение продолжает работать без сохранения (запись идёт в память
    на время сессии), игрок видит сообщение;
  - `skip` — запись не выполняется, игрок видит сообщение.
- Ошибка хранилища при старте не блокирует игру: карта открывается, счёт 0 или
  сохранённый, сообщение показывается поверх.

### TR-72. Провал сохранения не зачитывает очки

- Успешность записи статистики **обязана** быть явной для вызывающего кода
  (результат операции), а не определяться «по факту отсутствия исключения».
- Если запись общего счёта не удалась:
  - очки раунда **не зачитываются** (общий счёт не меняется);
  - игрок видит сообщение об ошибке (TR-71);
  - экран результатов не пишет «Заработано: N ✓» как зачтённое — строка помечается
    как незачтённая (тем же текстом, что и при проваленном раунде: `(не зачтено)`).
- Если раунд провален — поведение прежнее: очки сгорают, показывается `(не зачтено)`.
- Write-ahead сохраняется: память меняется только после успешной записи на диск.

### TR-73. Блокировка второй вкладки

- Первая (уже открытая) вкладка — **владелец сессии**; она продолжает работу и
  **не показывает** модалку «Игра уже запущена».
- Вторая вкладка **обнаруживает** занятую сессию, показывает модалку
  «Игра уже запущена» / «Закройте другую вкладку с MathLingo.» и **не начинает игру**.
- Закрытие вкладки-владельца освобождает сессию: следующая открытая вкладка
  запускается без модалки.
- Механизм обнаружения — на усмотрение агента (ответ владельца на `hello`,
  heartbeat-метка владельца и т. п.), но:
  - семантика одинакова для основного канала и для fallback;
  - fallback через `ml_session_lock` сохраняется и проверяется отдельно;
  - сценарий проверяется **автоматически** (вторая вкладка → модалка во второй,
    владелец без модалки).
- Текст модалки не меняется.

### TR-74. Актуальный общий счёт на карте

- Карта показывает счёт из хранилища на **любом** пути возврата: «На карту»,
  ✕ во время игры, выход после «Играть снова», смена карты, F5.
- Переход «игра → карта» **обязан** читать статистику заново; путь ✕ не исключение.
- Состояние гонки из P4 (карта обновилась до начисления очков) запрещено: показ карты
  и запись очков упорядочены так, чтобы показанный счёт уже включал завершённый раунд.

### TR-75. Пороги оценки — из `CONFIG.RATINGS`

- `GameRules.getRating` сравнивает точность с порогами `CONFIG.RATINGS[].min`,
  а не с литералами 100/70/40.
- Порядок проверок прежний: `lives <= 0` → `CONFIG.GAMEOVER`; далее — убывающие
  пороги; округление точности — один раз, до сравнения.
- Правка порога в `CONFIG` меняет оценку без правок кода; это проверяется тестом.

### TR-76. Бюджет строк

- `src/**/*.ts(x)` — не больше 200 строк на файл; `useMap.ts` сокращается до ≤ 200
  без изменения поведения (шапка/комментарии/дубли, как в D25 PLAN 1.8.2).
- Сьюты `test/**/*.test.ts(x)` — не больше 200 строк; превышение устраняется
  сокращением фикстур и хелперов, **не** удалением сценариев и не дроблением сьюта (A60).
- `scripts/**/*.mjs` — не больше 250 строк; при превышении хелперы выносятся
  в отдельный модуль (как `scripts/cdp.mjs`).
- `css/**/*.css` — не больше 200 строк; партиалы мелкие, лимит фиксируется для полноты
  контракта T76.
- Бюджет измеряется `wc -l` и входит в критерий TR-80; «разобью потом» не допускается.

### TR-77. Диагностика: миграции и ошибки

- Противоречие T11 («миграции логируются») и запрета `console.log` снимается так:
  диагностика ведётся через `console.info` / `console.warn` / `console.error`;
  `console.log` в `src/` остаётся запрещённым.
- Каждая выполненная ступень миграции `1 → 2 → 3` логируется один раз с номерами
  версий; повторная загрузка без миграции ничего не пишет.
- Ошибки хранилища логируются `handleError()` как раньше; игровые сообщения
  показываются модалкой (TR-71).

### TR-78. Контракт действий `ErrorInfo`

- `ErrorInfo.action` — ровно `'reset' | 'skip' | 'memory'`; `retry` из правил
  исключается как несуществующий в поведении.
- Каждое действие покрыто тестом «действие применено», а не только «классификация вернула».
- Новое действие добавляется только вместе с новой версией spec/rules и сценарием.

### TR-79. Гигиена репозитория и документации

- `.idea/` удаляется из индекса git и добавляется в `.gitignore`; `.npm-cache/`
  добавляется в `.gitignore` (Z37).
- `PLAN.md` / `TASKS.md` описывают **текущую** версию; версионированные файлы —
  только архивы предыдущих версий. Дубль текущего плана (`PLAN_v1_10_0.md` при
  заполненном `PLAN.md`) не создаётся; существующий `PLAN_v1_9_0.md` удаляется
  или помечается как архив в индексе — решение фиксируется в PLAN 1.10.0.
- `SPEC.md` и `RULES.md` перечисляют все версии; `TASKS_v1_10_0.md` создаётся по

- README/GIGACODE обновляются: число браузерных проверок после TR-73, структура

## ⚠️ Решения и риски

| # | Решение | Следствие |
|---|---------|-----------|
| 1 | Ошибки показываются существующим `ErrorModal` через единственный `showError` | Новых UI-компонентов нет; нужен тест на модалку из data-слоя |
| 2 | Успешность записи — явный результат метода сервиса | Ломает «тихую» сигнатуру `void`; тесты обновляются осознанно |
| 3 | Режим «память вместо диска» локален для сессии и живёт в data-слое | Не глобальный флаг; тестируется через `MemoryRepository` |
| 4 | Блокировка вкладок — handshake с владельцем или heartbeat | Текущий тест-инверсия переписывается; браузерный сценарий добавляется |
| 5 | Обновление карты идёт через один путь `reload()` | ✕ и «На карту» больше не расходятся по свежести счёта |
| 6 | Пороги — данные из `CONFIG.RATINGS`, поиск по убыванию `min` | Правка `RATINGS` становится значимой; тест на порог |
| 7 | `console.info` разрешён явно | Снимает конфликт T11 ↔ Z3; `console.log` остаётся запрещён |
| 8 | Бюджет строк ужесточается до `src`/`test` ≤ 200, `scripts` ≤ 250 | `useMap.ts` и 4 сьюта приводятся в норму без потери сценариев |
| 9 | `.idea/` убирается из индекса, а не игнорируется молча | История git не переписывается, только индекс |

**Риски и меры**

- **Инверсия блокировки вкладок.** Мера: браузерный сценарий на две цели CDP + отдельный
  тест хука, где сообщение владельца приходит во вторую вкладку.
- **Возврат `boolean` из сервиса.** Мера: обновить фейковые `Services` в тестах и T51-контракт.
- **Режим памяти.** Мера: тест на то, что при недоступном хранилище повторный `load`
  возвращает данные из памяти, а основной репозиторий не вызывается.
- **`useMap.ts`.** Мера: сокращать комментарии/шапку, не менять логику; тесты карты зелёные.
- **Логирование миграций.** Мера: спай на `console.info`, повторная загрузка не логирует.
