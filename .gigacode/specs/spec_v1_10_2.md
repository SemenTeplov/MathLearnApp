## 📋 Требования

### TR-89. Позиция после раунда совпадает с сохранённой

- `useMap.gameFinished(isSuccessful)`:
  - повторная игра (`isReplay()`) — ранний выход без записи и без синхронизации (A28/T23);
  - целевой индекс: победа — `player.index`, провал на новом — `player.previous`;
  - `saveTrainerIndex(target) === true` → `commitWin()` / `revert()`, отображение = `player.index`;
  - `saveTrainerIndex(target) === false` → `commitWin`/`revert` **не вызываются**, `PlayerState`
    приводится к индексу из хранилища (`restore(PlayerRules.normalizeIndex(getTrainerIndex(), total))`),
    отображение = этот индекс, `totalScore` — из хранилища; сообщение уже опубликовано
    сервисом (A79);
  - **инвариант:** после завершения раунда при любом исходе
    `stats.currentTrainerIndex === services.stats.getTrainerIndex()`.
- `PlayerState.restore(index)` — синхронизация с хранилищем: `_current = _previous = index`,
  возвращает индекс. Отдельного «чернового» индекса и второго источника позиции не вводится.
- `total` для нормализации — число тренажёров текущей карты (в `useMap` — длина уже
  построенной геометрии или сумма `trainersCount` из `state.zones`); нормализация защищает
  от испорченного значения в хранилище.
- Тесты: (1) победа + `repo.save` бросает → UI = хранилище = прежний индекс, счёт раунда не
  зачтён, сообщение в шине; (2) проигрыш + `repo.save` бросает → UI = хранилище = предыдущий
  индекс; (3) успешные пути не изменились (победа закрепляет, провал откатывает, повтор
  позицию не пишет).

### TR-90. Один звук на одно открытие подтверждения

- `useGame.exit()`: только `onExitRequested(model.roundScore)` — без звука, без завершения
  раунда, без записи статистики.
- `App.handleExitRequested(roundScore)`: если подтверждение уже открыто — `return` (ни окна,
  ни звука, ни изменения состояния); иначе `audio.play('click')` и `setExitConfirm({ roundScore })`.
- «Выйти»: `click` → закрыть → `exitGame()` → `returnToMap()` (T82); «Остаться» и клик по
  оверлею: `click` → закрыть, раунд продолжается.
- Тексты и разметка `ConfirmModal` не меняются (T80).
- Тесты: два ✕ → ровно один `click` и одна модалка; «Остаться» — один `click`; `exit()` не
  вызывает `audio.play`; повторный `onExitRequested` не дублирует ни окно, ни звук.

### TR-91. Сообщения показываются очередью, ни одно не теряется

- Состояние `App`: очередь `{ title: string; message: string }[]`; `showError(title, message)`
  добавляет сообщение в конец.
- Показывается **первое** сообщение очереди; «OK» и клик по оверлею снимают первое и играют
  `click`; при пустой очереди модалки нет.
- Порядок — публикации (FIFO); сообщение не заменяется и не отбрасывается; дедупликация
  остаётся в источнике (A79/Z44), оболочка сообщения не фильтрует и не склеивает.
- Повторная подписка (StrictMode) уже доставленные сообщения не повторяет (A86 сохраняется);
  второй канал показа не вводится (Z44).
- Тесты: (1) два `report()` подряд → видно первое, после «OK» — второе, затем модалки нет;
  (2) повреждённое хранилище + `busy` второй вкладки → сначала «Ошибка хранилища», после
  «OK» — «Игра уже запущена»; (3) StrictMode — без дублей.

### TR-92. Статистика читается один раз за экземпляр

- `StatsService` хранит `_cache: Stats | null`; `load()` возвращает кэш, если он есть, иначе
  читает (`_read()`), мигрирует, делает write-back (A89) и кладёт результат в кэш.
- Успешная запись (`save`, `_writeBack`) обновляет кэш сохранённым значением (глубокая копия,
  A12); `updateAfterRound`, `saveTrainerIndex`, `switchMap`, `reset` получают обновление
  через `save`.
- `_toMemory()` и ошибка чтения кэш сбрасывают; ошибка чтения не кэшируется (повторное
  обращение снова идёт в хранилище один раз).
- Кэш живёт в экземпляре сервиса (A78): не `window.*`, не `globalThis.*`, не модульная
  переменная.
- Запрещено мутировать объект, полученный из `load()`: write-методы по-прежнему клонируют
  (A12), геттеры только читают.
- Тесты: (1) три геттера подряд → `repo.load()` вызван один раз; (2) первый рендер `App` в
  StrictMode → одно чтение; (3) после `updateAfterRound` счёт читается из кэша, новых чтений
  нет; (4) после `switchMap` карта и счёт читаются из кэша; (5) провал `save` не меняет кэш;
  (6) режим «память» сбрасывает кэш и далее читает из памяти.

## 🚫 Вне области 1.10.2

- **Перенос первичного чтения из рендера в эффект.** Кэш (A95/TR-92) делает чтение
  однократным; перестройка порядка «рендер → эффект» меняет первый кадр карты и выносится
  отдельным этапом.
- **Устойчивость `ErrorBus` к исключению слушателя и ограничение `_pending`.** Слушатель —
  `setState`, исключений не даёт; сценарий не воспроизводится, размер очереди ограничен
  количеством ошибок за сессию.
- **Исключения из репортёра внутри `_recover`.** `report()` в `App` — `setState`, бросить не
  может; защита не требуется, пока не появится второй репортёр.
- Гонка двух вкладок, открытых одновременно (tie-break не вводится), и разблокировка уже
  открытой второй вкладки после закрытия владельца — известные ограничения 1.10.0/1.10.1.
- Новая функциональность (серии, бонусы, таймеры, достижения), редизайн, правка значений
  стилей и текстов существующих подсказок; новые рантайм-зависимости; Playwright/Puppeteer;
  type-aware ESLint; Prettier для `.md`; смена версий React/Vite/Vitest/TypeScript.
- Изменение `CONFIG`, формата `Stats` v3, ключей `ml_stats`/`ml_session_lock`, карты, звуков.
