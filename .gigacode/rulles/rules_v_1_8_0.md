## 🏛️ Архитектурные принципы — дополнения (1.8.0)

### A41. Миграция экранов — по одному

**Правило:** каждый экран мигрируется **отдельно**.

**Правила:**

- **Один** экран — **одна** задача
- **После** каждого — **игра работает**
- **Порядок** — от **простого** к **сложному**
- **Не** мигрировать **два** экрана **одновременно**

### A42. Порядок миграции

**Правило:** порядок **фиксирован**.

**Правила:**

1. **Результаты** (простой)
2. **Модалка выбора карты** (простой)
3. **Игра** (средний)
4. **Карта** (сложный)
5. **Шапка** (простой)
6. **Экран приветствия** (удаление)

**Причина:** от **простого** к **сложному** — **меньше** риска.

### A43. Старые файлы — удалять после миграции

**Правило:** после миграции экрана — **старые** файлы **удаляются**.

**Правила:**

- `view/*.js` — **удалить** после **замены**
- `controller/*.js` — **удалить** после **замены**
- **Не** оставлять **мёртвый** код
- **Git-коммит** после **каждого** экрана

### A44. Компоненты — функциональные

**Правило:** все компоненты — **функциональные**.

**Правила:**

- **Никаких** классовых компонентов
- **Хуки** — для **состояния** и **эффектов**
- **Пропсы** — **типизированы** через **интерфейсы**

### A45. Состояние — локальное (пока)

**Правило:** на Этапе 3 — **локальное** состояние.

**Правила:**

- **`useState`** / **`useReducer`** — **внутри** компонентов
- **Глобальное** состояние — **позже** (Этап 4)
- **Props drilling** — **допускается** (временно)

### A46. CSS — существующий

**Правило:** CSS **не** меняется на Этапе 3.

**Правила:**

- **Классы** — **те же**
- **Стили** — **те же**
- **Новые** стили — **только** если **критично**
- **Рефакторинг** CSS — **позже** (Этап 5)

### A47. Движение игрока — CSS transition

**Правило:** движение игрока — **через** CSS **transition**.

**Правила:**

- **`transform: translate()`** — **позиция**
- **`transition: 600ms`** — **плавность**
- **`onTransitionEnd`** — **событие** завершения
- **Не** `requestAnimationFrame` (для простоты)

## 🔧 Технические ограничения — дополнения (1.8.0)

### T36. Структура `src/`

**Правило:** все React-компоненты — **в** `src/`.

**Структура:**
src/
components/
ResultsScreen.tsx
GameScreen.tsx
MapScreen.tsx
MapSelectionModal.tsx
Header.tsx
ErrorModal.tsx
Zone.tsx
Trainer.tsx
Player.tsx
Path.tsx
hooks/
useStats.ts (позже, Этап 4)
useAudio.ts
useMap.ts
types.ts
config.ts
main.tsx
App.tsx

### T37. Компоненты — правила

- **Функциональные**
- **Пропсы** — **интерфейс** `ComponentNameProps`
- **Экспорт** — `export function ComponentName(...)`
- **JSX** — **без** `React.createElement`
- **`key`** — **обязательно** в **списках**

### T38. Хуки — правила

- **Только** в **функциональных** компонентах
- **Имя** — **начинается** с `use`
- **Не** вызывать **условно**
- **Зависимости** — **указывать** в `useEffect`

### T39. Обработчики — правила

- **`onClick`** — **не** `onclick`
- **`e.stopPropagation()`** — **где** нужно
- **`e.preventDefault()`** — **где** нужно
- **Не** вешать **обработчики** **напрямую** на **DOM**

### T40. SVG — дорога

- **`<svg>`** — **один** на **карту**
- **`<path>`** — **один** на **всю** дорогу
- **`d`** — **кубические** кривые (`C` или `Q`)
- **`viewBox`** — **растягивается** под **карту**

## ✅ Обязательства агента — дополнения (1.8.0)

При миграции экранов агент **обязан**:

1. **Мигрировать** экраны **по одному**
2. **Следовать** порядку (результаты → модалка → игра → карта → шапка → приветствие)
3. **Удалять** старые файлы **после** миграции
4. **Проверять** игру **после** каждого экрана
5. **Git-коммит** после **каждого** экрана
6. **Не** трогать CSS без необходимости
7. **Не** менять логику игры
8. **Типизировать** все компоненты
9. **Использовать** функциональные компоненты
10. **Сохранять** существующее поведение
