## 🏛️ Архитектурные принципы — дополнения (1.10.0)

### A79. Ошибка хранилища — это состояние UI, а не только запись в консоль

**Правило:** каждая ожидаемая ошибка хранилища доходит до игрока и меняет режим работы,
а не ограничивается `console.warn` и возвратом значений по умолчанию.

**Правила:**

- `handleError()` по-прежнему классифицирует ошибку и **не действует сам** (A11); действие
  применяет вызывающий;
- игровое сообщение берётся из `ErrorInfo.userMessage` и показывается существующей модалкой
  ошибок через **единственный** канал `showError` в `App.tsx`;
- `alert()` / `confirm()` для игровых сообщений запрещены (Z6);
- ошибка хранилища не блокирует игру: карта открывается, раунд играется;
- на одну ошибку — одно сообщение (без повторных показов на каждый `load()`).

**Причина:** аудит 1.9.0 показал, что `userMessage` создавался и тестировался, но не
использовался нигде, кроме теста: повреждение данных и недоступное хранилище сбрасывались
молча.

### A80. Провал записи откатывает обещание, а не только лог

**Правило:** если статистика не сохранилась, игрок не должен видеть зачтённые очки.

**Правила:**

- записывающие методы сервиса статистики возвращают явный результат (успех/провал),
  а не «void + исключение, которое никто не проверяет»;
- при провале: общий счёт не меняется, экран результатов показывает
  «Заработано: N (не зачтено)» и сообщение об ошибке (A79);
- write-ahead сохраняется: память меняется только после успешной записи (A12);
- проверка — тест с репозиторием, который бросает на `save`.

**Причина:** при `QuotaExceededError` `updateAfterRound` молча терял очки, а
`ResultsScreen` писал «Заработано: N ✓» (FR-11, Z7).

### A81. Владелец сессии — первая вкладка; блокируется вторая

**Правило:** уже открытая вкладка продолжает работу и молчит; новая вкладка обнаруживает
занятую сессию, сообщает об этом и не начинает игру.

**Правила:**

- вкладка-владелец не показывает модалку «Игра уже запущена»;
- новая вкладка обязана **сама** обнаружить занятость (ответ владельца на `hello`,
  heartbeat-метка владельца с TTL или эквивалент) — полагаться на то, что
  `BroadcastChannel.postMessage` вернётся отправителю, запрещено;
- пока сессия занята, новая вкладка не может начать раунд: старт игры и «Играть снова»
  не срабатывают, модалка показывается снова;
- закрытие владельца освобождает сессию;
- fallback `ml_session_lock` даёт **ту же** семантику; ключ и текст модалки не меняются;
- сценарий проверяется юнит-тестом хука и браузерным сценарием в `scripts/verify-dist.mjs`
  (без новых зависимостей).

**Причина:** в 1.9.0 модалку получала первая вкладка, а вторая играла — прямо против
A13 и US-18.

### A82. Карта читается перед показом

**Правило:** карта всегда показывает статистику из хранилища на момент показа.

**Правила:**

- любой переход «игра → карта» идёт через один путь: чтение статистики (`reload()` или
  эквивалент) и только затем `navigate('map')`;
- ✕ во время игры использует тот же путь, что «На карту»; отдельный «облегчённый» выход
  без перечитывания запрещён;
- показ карты не может предшествовать записи очков завершённого раунда: либо запись
  выполняется раньше, либо карта перечитывается после неё;
- производные значения не кэшируются в модульных переменных (A78).

**Причина:** путь «победа → результаты → „Играть снова“ → ✕» показывал счёт без только
что заработанных очков (FR-18).

### A83. Пороги оценки — данные, а не код

**Правило:** оценка считается только из фактических `correct`/`total` и порогов
`CONFIG.RATINGS`.

**Правила:**

- первым проверяется `lives <= 0` → `CONFIG.GAMEOVER`;
- далее пороги перебираются по убыванию `min` из `CONFIG.RATINGS`;
- литералы `100 / 70 / 40` в `src/**` запрещены;
- правка порога в `CONFIG` меняет оценку без правок кода; тест это фиксирует.

**Причина:** A50 требовал брать пороги из `CONFIG` ещё в 1.8.1, но `getRating` сравнивал
с числами, а `Rating.min` в `src/` не читался.

### A84. Бюджет строк — часть критерия готовности

**Правило:** размер файла проверяется автоматически так же, как тесты.

**Правила:**

- `src/**/*.ts(x)` — ≤ 200 строк; `test/**/*.test.ts(x)` — ≤ 200 строк;
  `scripts/**/*.mjs` — ≤ 250 строк; `css/**/*.css` — ≤ 200 строк;
- измерение — `wc -l`, входит в критерий T78;
- превышение устраняется сокращением шапок, комментариев, фикстур и дублей,
  а не удалением сценариев и не дроблением сьюта (A60);
- «временно больше 200» и «разобью потом» не допускаются.

**Причина:** регресс 1.9.0 — `useMap.ts` вырос с 200 до 209 строк при переформатировании,
а `test/README.md` требовал ≤ 200 строк для сьюта, который не проверялся.

### A85. Диагностика — `info` / `warn` / `error`

**Правило:** диагностика ведётся разрешёнными каналами; `console.log` в `src/**`
остаётся запрещённым.

**Правила:**

- `console.log` в `src/**` запрещён (Z3 1.0.0); для диагностики используются
  `console.info`, `console.warn`, `console.error`;
- каждая выполненная ступень миграции `1 → 2 → 3` логируется один раз с номерами версий;
  загрузка без миграции ничего не пишет;
- логирование не дублируется на каждый вызов `load()`;
- сообщение об ошибке игроку (A79) не подменяется записью в консоль.

**Причина:** T11 требовал логировать миграции, а конституция запрещала `console.log` —
противоречие не было снято; миграции в 1.9.0 не логировались вообще.

## 🔧 Технические ограничения — дополнения (1.10.0)

### T71. Контракт `ErrorInfo` и применения действий

```ts
export type ErrorAction = 'reset' | 'skip' | 'memory';

export interface ErrorInfo {
    action: ErrorAction;
    userMessage: string;
}
```

- `retry` из A11 исключается: в поведении такого действия нет, тип его не содержит;
- `handleError(error, context)` возвращает `ErrorInfo` и логирует системную ошибку;
- вызывающий применяет действие:
  - `reset` — очищает повреждённую запись (`Repository.clear()`) и продолжает со значениями
    по умолчанию;
  - `memory` — переводит статистику в режим «память вместо диска» до конца сессии;
  - `skip` — не выполняет запись;
- записывающие методы `StatsService` (`save`, `updateAfterRound`, `saveTrainerIndex`,
  `switchMap`, `reset`) возвращают результат операции; `updateAfterRound` возвращает
  `false`, если счёт не сохранён;
- фейковый `Services` в тестах обновляется под новый результат (T51 1.8.3).

### T72. Контракт режима «память вместо диска»

- переключение живёт **внутри data-слоя**: резервный `MemoryRepository` за декоратором
  `Repository` либо явный режим в `StatsService`; сигнатура `Repository` не меняется;
- глобальные переменные, `window.*` и `globalThis.*` как канал состояния запрещены (A78);
- переключение идемпотентно и не переживает перезагрузку страницы;
- пока режим активен, основной репозиторий для чтения/записи не вызывается;
- тест: основной репозиторий бросает на `load`/`save` → игра работает, значения
  читаются из памяти, основной репозиторий больше не дёргается.

### T73. Контракт блокировки вкладок

- канал — `BroadcastChannel('mathlingo_session')`, сообщение `'hello'`; владелец отвечает
  `'busy'` (или пишет heartbeat-метку с TTL в `localStorage`);
- новая вкладка, получив признак занятости, вызывает `showError('Игра уже запущена',
  'Закройте другую вкладку с MathLingo.')` **у себя** и переходит в заблокированный режим:
  `startGame` и «Играть снова» не срабатывают, модалка показывается снова;
- владелец по `hello` не показывает модалку и продолжает работу;
- cleanup снимает heartbeat/закрывает канал; в `StrictMode` эффект идемпотентен;
- fallback без `BroadcastChannel`: занятый `ml_session_lock` → модалка у новой вкладки;
  свободный → запись ключа; семантика и текст сообщения совпадают с основным каналом;
- автоматическая проверка: юнит-тест хука (модалка у претендента, тишина у владельца)
  и сценарий в `verify-dist.mjs` на две цели CDP; новых зависимостей нет.

### T74. Контракт свежести карты

- возврат на карту — один обработчик: `reload()` + `navigate('map')`; ✕ вызывает его же;
- `onRoundFinished` (позиция на карте) и запись очков упорядочены так, чтобы состояние
  карты не фиксировало счёт раньше записи;
- тест-последовательность: счёт 0 → победа 10/10 → результаты → «Играть снова» → ✕ →
  в шапке карты `🏆 100`;
- «На карту» даёт тот же результат (регресс не допускается).

### T75. Контракт `CONFIG.RATINGS`

- массив отсортирован по убыванию `min`; последний элемент — с `min: 0`;
- `getRating` перебирает `RATINGS` подряд, не сравнивая с литералами;
- `accuracy` округляется один раз, до сравнения;
- тест: изменение `min` в копии `CONFIG` (или подстановка) меняет возвращаемую оценку.

### T76. Бюджет строк

| Область | Лимит (`wc -l`) |
|---|---|
| `src/**/*.ts`, `src/**/*.tsx` | 200 |
| `test/**/*.test.ts`, `test/**/*.test.tsx` | 200 |
| `scripts/**/*.mjs` | 250 |
| `css/**/*.css` | 200 |

- бюджет проверяется в критерии T78 и в CI-прогоне (локально достаточно команд из T78);
- превышение — дефект, а не вкусовщина; исправляется сокращением незначащих строк.

### T77. Гигиена git и документов

- `.gitignore` содержит `node_modules/`, `dist/`, `coverage/`, `*.log`, `.npm-cache/`, `.idea/`;
- `.idea/` убирается из индекса (`git rm -r --cached .idea`); история git не переписывается;
- `PLAN.md` и `TASKS.md` описывают текущую версию; версионированные `PLAN_vX` / `TASKS_vX` —
  только архивы предыдущих версий; дубль текущего плана не создаётся;
- `SPEC.md` и `RULES.md` перечисляют все версии; `TASKS_v1_10_0.md` создаётся по процедуре;
- README и GIGACODE обновляются вместе с кодом: число браузерных проверок после T73,
  структура без `.idea/`, бюджет строк, диагностика `console.info`, версия `1.10.0`
  в `package.json`;
- документы не ссылаются на несуществующие команды и файлы (T69).

## 🚫 Запреты — дополнения (1.10.0)

### Z39. Запрещено в обработке ошибок

- молча сбрасывать повреждённые данные или игнорировать недоступное хранилище без
  сообщения игроку;
- показывать очки зачтёнными, если запись не удалась;
- использовать `alert()` / `confirm()` для игровых сообщений;
- плодить второй канал показа ошибок в обход `showError`;
- пустой `catch` без комментария-обоснования: для необязательных браузерных API
  (`BroadcastChannel`, `localStorage` в блокировке сессии) допустим осознанный no-op
  catch **с комментарием**, объясняющим, почему ошибка не важна.

### Z40. Запрещено в блокировке сессии

- показывать модалку «Игра уже запущена» вкладке-владельцу;
- рассчитывать на возврат `postMessage` отправителю или иной самообман вместо реального
  обнаружения занятости;
- позволять новой вкладке начать раунд при занятой сессии;
- хранить признак сессии в модульной переменной или `window.*` вместо канала/метки.

### Z41. Запрещено в данных и оценке

- литералы порогов оценки (`100`, `70`, `40`) в `src/**`;
- менять значения `CONFIG`, `RATINGS`/`GAMEOVER`, формат `Stats` v3, ключи
  `ml_stats` / `ml_session_lock`;
- писать статистику в обход write-ahead (A12) или до успешной записи;
- сохранять промежуточное состояние раунда и очки до завершения раунда (Z7 1.1.0).

### Z42. Запрещено в бюджете и тестах

- файл длиннее лимита T76 в `src/`, `test/`, `scripts/`, `css/`;
- удалять, скипать или ослаблять сценарии ради соблюдения бюджета;
- дробить сьют вместо сокращения фикстур (A60 1.8.3);
- понижать пороги покрытия или число тестов;
- `console.log` в `src/**`;
- «потом разобью» и «временно больше».

### Z43. Запрещено в этом этапе

- новая функциональность игры (серии, бонусы, таймеры, достижения), редизайн и правка
  значений стилей;
- новые рантайм-зависимости, Playwright/Puppeteer, type-aware ESLint, Prettier для `.md`;
- смена версий React/Vite/Vitest/TypeScript;
- переписывание истории git (`rebase -i`, `reset --hard`, force-push) ради удаления
  `.idea/` из истории;
- изменение публичного контракта `Repository`/хуков сверх T71–T73.
