## 🎯 Назначение

Этот документ задаёт **незыблемые правила** проекта MathLingo. ИИ-агент **обязан** следовать им при генерации, изменении или рефакторинге кода.

При конфликте между `constitution.md` и любым другим документом (`spec.md`, `plan.md`, `tasks.md`) — **побеждает `constitution.md`**.

## 🏛️ Архитектурные принципы

### A1. Строгое разделение слоёв

Проект использует **четырёхслойную архитектуру**:

| Слой | Ответственность | Знает о |
|------|-----------------|---------|
| **Model** | Хранение данных, состояние | Ни о ком |
| **Logic** | Правила игры, алгоритмы | Model |
| **View** | Отрисовка DOM | Model (только чтение) |
| **Controller** | Связка слоёв, обработка событий | Model, Logic, View |

### A2. Направление зависимостей

Controller → Logic → Model
Controller → View → Model


**Запрещено** обратное направление. Model **не знает** о Logic, View, Controller.

### A3. Model — только данные

Model содержит **только**:
- Поля состояния
- Геттеры для чтения
- Сеттеры для записи
- Метод `reset()`

Model **не содержит**:
- Бизнес-правил
- Расчётов очков
- Проверок ответов

### A4. Logic — только правила

Logic содержит **только**:
- Генерацию задач
- Расчёт очков
- Проверку ответов
- Правила переходов между состояниями

Logic **не содержит**:
- Ссылок на DOM
- `document`, `window`, `localStorage`
- Отрисовки

### A5. View — только отрисовка

View содержит **только**:
- Ссылки на DOM-элементы
- Функции отрисовки (render*)
- Чтение Model

View **не содержит**:
- Бизнес-логики
- Расчётов
- Изменения Model

### A6. Controller — единственная связка

Controller — **единственный слой**, который:
- Слушает DOM-события
- Вызывает функции Logic
- Командует View

Controller **не содержит**:
- Бизнес-правил
- Прямых манипуляций с DOM (только через View)
- Прямого изменения Model (только через Logic)

### A7. Поток данных

**Ввод:** `DOM event → Controller → Logic → Model`  
**Вывод:** `Model → Controller → View → DOM`

## 🔧 Технические ограничения

### T1. Стек

- **JavaScript ES2020+**. Без TypeScript, без Babel, без сборщиков.
- **CSS3**. Без препроцессоров.
- **HTML5**. Без шаблонизаторов.
- **Никаких внешних зависимостей**: без React, Vue, jQuery, Lodash, Axios.
- **Никаких CDN**. Всё локально.

### T2. Модульность

- Каждый файл — **одна ответственность**.
- Файл **≤ 200 строк**. Если больше — разбить.
- CSS — модульный, каждая точка входа через `@import` собирает подмодули.
- JS — модульный, каждый файл в своей папке слоя (`model/`, `logic/`, `view/`, `controller/`).

### T3. Порядок подключения

JS-файлы подключаются **строго** в порядке:

model/types.js
model/config.js
model/game-model.js
model/storage.js
model/stats-service.js
logic/generator.js
logic/scoring.js
logic/game-rules.js
view/dom.js
view/screen-view.js
view/game-view.js
view/results-view.js
controller/app-controller.js
controller/game-controller.js
controller/results-controller.js
script.js


**Правило:** файл использует только то, что объявлено **выше** в списке.

### T4. Именование файлов

- CSS: `kebab-case.css` — `game-header.css`
- JS: `kebab-case.js` — `game-rules.js`
- Документы: `UPPERCASE.md` или `lowercase.md` — `constitution.md`

### T5. Именование в коде

| Сущность | Стиль | Пример |
|----------|-------|--------|
| Переменная | `camelCase` | `currentQuestion` |
| Константа | `UPPER_SNAKE` | `MAX_LIVES` |
| Класс | `PascalCase` | `ProblemGenerator` |
| Функция | `camelCase` | `submitAnswer()` |
| Приватное поле | `#camelCase` | `#count` |
| Глобальный объект-модуль | `PascalCase` | `GameRules` |
| DOM-элемент | `camelCase` | `nextBtn` |
| CSS-класс | `kebab-case` | `.answer-btn` |
| CSS-модификатор | `--modifier` | `.answer-btn--correct` |

### T6. Стиль кода

- Отступ: **4 пробела** (не табы)
- Кавычки: **одинарные** `'`
- Точка с запятой: **обязательна**
- Длина строки: **≤ 100 символов**
- Фигурные скобки: **на той же строке** (K&R)
- Пробел после запятой, вокруг операторов

```javascript
// ✅ Правильно
function calculate(a, b) {
    return a + b;
}

// ❌ Неправильно
function calculate(a,b){
return a+b
}
```

### T7. Комментарии и JSDoc

JSDoc обязателен для всех публичных функций
Однострочные комментарии — //
Многострочные — /* */
Секции файла — разделители // ===== ... =====

```javascript
/**
 * Считает очки за правильный ответ.
 * @param {number} streak — текущая серия
 * @returns {number} количество очков
 */
function calculateScore(streak) {
    return CONFIG.POINTS_BASE + streak * CONFIG.POINTS_STREAK_BONUS;
}
```

### T8. Формат данных

Все данные между слоями передаются plain-объектами (DTO):

```javascript
javascript
// ✅ Правильно — plain object
{ question: '2+2', answer: 4, options: [3, 4, 5, 6], explanation: '2+2=4' }

// ❌ Неправильно — класс-обёртка
class Question { constructor(...) { ... } }
DTO описываются через JSDoc @typedef в model/types.js.
```
