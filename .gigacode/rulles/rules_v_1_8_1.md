## 🏛️ Архитектурные принципы — дополнения (1.8.1)

### A48. Счётчики ответов — единственный источник истины

**Правило:** число правильных и неправильных ответов **считается при ответе**, а не
вычисляется на экране результатов.

**Правила:**

- `recordCorrect()`: `_correct++`, `_roundScore += POINTS_BASE`
- `recordIncorrect()`: `_wrong++`, `_lives--`
- `getResults()` только **читает** счётчики
- **Запрещено** выводить `correct`/`wrong` из `_currentQuestionIndex`, `_roundScore`,
  `POINTS_BASE`, `_lives` или DOM
- **Причина:** индекс — число завершённых вопросов, а не правильных; на этом вырос баг 1.8.0

### A49. `total` — фактически отвечено

**Правило:** `total = correct + wrong`.

**Правила:**

- завершённый раунд (10 ответов): инвариант `correct + wrong = TOTAL_QUESTIONS = 10`
- досрочное окончание: `total` может быть меньше 10, оценка — «Игра окончена»
- `TOTAL_QUESTIONS` — **не** знаменатель точности: неотвеченные вопросы не являются ошибками,
  а «0 из 10» после трёх ответов вводит в заблуждение
- решение фиксируется комментарием в `getResults()` и тестом на 0/3 (`total = 3`)
- при `total = 0` точность — 0 (без деления на ноль)

### A50. Оценка — только из `CONFIG`

**Правило:** оценка считается из фактических `correct`/`total` и порогов `CONFIG.RATINGS`.

**Правила:**

- первым проверяется `lives <= 0` → `CONFIG.GAMEOVER`
- `accuracy = Math.round(correct / total * 100)`
- пороги 100/70/40/0 берутся из `CONFIG.RATINGS`, не хардкодятся
- округление — один раз, до сравнения с порогом
- 8/2 → 80 → «Отлично!»; 10/10 → 100 → «Идеально!»

### A51. `reset()` — полный сброс раунда

**Правило:** новый раунд начинается с нулевых счётчиков.

**Правила:**

- `reset()` обнуляет `_correct` и `_wrong` вместе с `_lives`, `_roundScore`,
  `_currentQuestionIndex`, `_difficulty`, `_completed`
- после `reset()` `getResults()` → 0/0/0
- не «забывать» новые поля при добавлении следующих

## 🔧 Технические ограничения — дополнения (1.8.1)

### T41. `SessionModel` — поля и API

**Поля:** `_lives`, `_roundScore`, `_correct`, `_wrong`, `_currentQuestionIndex`,
`_difficulty`, `_completed`.

**Методы (сигнатуры не менять):**

- `recordCorrect(): void`
- `recordIncorrect(): void`
- `reset(): void`
- `getResults(): GameResult`

**Контракт `getResults()`:**

```ts
{
    correct: this._correct,
    wrong: this._wrong,
    total: this._correct + this._wrong, // фактически отвечено (A49)
    roundScore: this._roundScore,
    lives: this._lives,
    completed: this._completed
}
```

- Публичные геттеры `correct`/`wrong` — по желанию, только чтение; сеттеры не добавлять.
- `setLives`/`setRoundScore`/`setDifficulty`/`setCompleted` сохраняются.
- `advanceQuestion()` продолжает двигать индекс — на счётчики не влияет.

### T42. Тест `SessionModel`

**Файл:** `test/model/session-model.test.js`.

- Загрузка исходника: `readSource('./js/model/session-model.ts')` + `eval` +
  `global.SessionModel` (как в `stats-service.test.js`).
- `CONFIG` берётся из `test/setup.js`, не дублируется в тесте.
- Тест **вызывает** модель, а не переписывает её логику (в отличие от `scoring.test.js`).
- Блоки: `recordCorrect`, `recordIncorrect`, `getResults`, `reset`.
- Обязательный минимум — 4 приёмочных сценария из спеки (8/2, 10/10, 0/3, reset) +
  `total = correct + wrong` + `total = 0` без ответов.
- Перед фиксом тест 8/2 должен **падать** — это доказательство бага.

### T43. Совместимость

- `GameResult` не расширяется и не переименовывается.
- `ResultsScreen`, `useResults`, `GameRules.getRating` не меняют API.
- Исправление локализовано в `js/model/session-model.ts`; остальные слои не правятся.
- `src/types.ts` не меняется.
