## 🏛️ Архитектурные принципы — дополнения (1.10.2)

### A92. Провал записи позиции синхронизирует игрока с хранилищем

**Правило:** после завершения раунда отображаемая позиция игрока совпадает с сохранённой —
независимо от того, удалась запись или нет.

**Правила:**

- целевой индекс вычисляется до записи: победа — вперёд, провал на новом — назад (A80);
- `saveTrainerIndex(target) === true` → `PlayerState` фиксируется (`commitWin()` / `revert()`),
  отображение = `player.index`;
- `saveTrainerIndex(target) === false` → ни `commitWin()`, ни `revert()` не вызываются;
  `PlayerState` приводится к индексу из хранилища через `restore(PlayerRules.normalizeIndex(
  getTrainerIndex(), total))`, отображение = этот же индекс, `totalScore` читается из
  хранилища; сообщение игроку уже опубликовано сервисом (A79);
- инвариант: после раунда при любом исходе
  `stats.currentTrainerIndex === services.stats.getTrainerIndex()`;
- `PlayerState.restore(index)` сбрасывает и текущую, и точку отката (`previous = index`):
  игрок «стоит» на сохранённом тренажёре, повторная игра на нём — replay (A28/T23);
- второй источник позиции («черновой» индекс, `lastAttempt`) не вводится.

**Причина:** в 1.10.1 при провале записи `setState` брал `player.index` (позицию клика), а не
сохранённую. Замер: победа → UI 1 / хранилище 0, проигрыш → UI 1 / хранилище 0. На проигрыше
это регресс относительно 1.10.0 (там `revert()` вызывался до записи и давал 0/0), а обещание
плана «после F5 расхождения нет» не выполнялось ни на одном пути.

### A93. Один жест — один звук; выход подтверждается один раз

**Правило:** звук выхода играет оболочка ровно в момент открытия подтверждения; повторный ✕
при открытой модалке не производит ничего.

**Правила:**

- `useGame.exit()` только сообщает о желании выйти (`onExitRequested(roundScore)`) — без
  звука, без завершения раунда, без записи статистики;
- `App.handleExitRequested(roundScore)`: подтверждение уже открыто → `return`; иначе
  `audio.play('click')` и открытие `ConfirmModal`;
- звук не играется внутри апдейтера состояния (StrictMode вызывает апдейтеры дважды);
- «Выйти» / «Остаться» / клик по оверлею — по одному `click` на нажатие (T80);
- тексты и разметка `ConfirmModal` не меняются.

**Причина:** `exit()` играл `click` до идемпотентной проверки в `App`, поэтому второй ✕ давал
второй звук при одной модалке — T80 запрещает дублировать «ни окно, ни звук».

### A94. Сообщения игроку показываются очередью, ни одно не теряется

**Правило:** в оболочке существует очередь сообщений: показывается первое, закрытие снимает
первое, остальные ждут.

**Правила:**

- состояние — массив `{ title, message }` в `App`; `showError` добавляет в конец;
- модалка рендерится для первого элемента; «OK» и клик по оверлею снимают ровно один элемент;
- порядок — публикации (FIFO); сообщение не заменяется другим и не отбрасывается;
- дедупликация остаётся в источнике (A79/Z44); оболочка сообщения не фильтрует и не склеивает;
- очередь живёт в состоянии компонента (A78): не `window.*`, не `globalThis.*`, не модульная
  переменная; второй канал показа не вводится (Z44);
- повторная подписка (включая `StrictMode`) уже доставленные сообщения не повторяет (A86).

**Причина:** в 1.10.1 было одно поле `error`. Шина доставила стартовую ошибку хранилища
(`ErrorBus` больше не теряет, A86), но `busy` второй вкладки затирал её в том же коммите:
игрок видел только «Игра уже запущена». Та же потеря — при любых двух ошибках подряд.

### A95. Статистика читается один раз за экземпляр сервиса

**Правило:** `StatsService` кэширует последнюю прочитанную/записанную статистику; после
прогрева геттеры не обращаются к хранилищу.

**Правила:**

- `_cache: Stats | null` в экземпляре; `load()` возвращает кэш, если он есть;
- кэш наполняется результатом чтения (после миграции и write-back, A89) и обновляется каждой
  успешной записью (`save`, `_writeBack`), включая `updateAfterRound`, `saveTrainerIndex`,
  `switchMap`, `reset`;
- `_toMemory()` и ошибка чтения кэш сбрасывают; ошибка чтения не кэшируется;
- объект из `load()` нельзя мутировать — write-методы клонируют (A12); кэш хранит копию;
- кэш — не глобальное состояние (A78): только поле экземпляра.

**Причина:** 1.10.1 читала хранилище на каждый геттер: 3 `repo.load()` + `JSON.parse` на
инициализацию карты (6 в dev StrictMode), плюс I/O и write-back в фазе рендера. Очередь шины
(A86) маскировала симптом P1, но корень — лишние чтения — оставался.

### A96. Порт публикует, адаптер подписывает

**Правило:** `ErrorReporter` в `core` — только публикация; подписка и очередь — обязанность
адаптера `ErrorBus` в `app`.

**Правила:**

- `src/data/**` видит только `ErrorReporter` (`report`) и не знает про `subscribe`;
- `ErrorBus` реализует порт структурно и добавляет `subscribe`/очередь недоставленных (T79);
- `Services.errors` остаётся `ErrorBus`; `App` подписывается на адаптер и показывает
  сообщения очередью (A94);
- циклы слоёв запрещены (A87/Z45).

**Причина:** TR-82 в 1.10.1 утверждал, что «App работает с шиной через порт», но `subscribe` в
порт не входит, а `Services.errors` типизирован `ErrorBus`. Слои не нарушены — расходилась
только формулировка; она уточняется в T90.3.

## 🔧 Технические ограничения — дополнения (1.10.2)

### T86. Контракт синхронизации позиции

```ts
// src/core/player-state.ts — единственный способ синхронизации с хранилищем
restore(index: number): number {
    this._current = index;
    this._previous = index;
    return index;
}
```

```ts
// src/hooks/useMap.ts — завершение раунда
const target = isSuccessful ? player.index : player.previous;
if (services.stats.saveTrainerIndex(target)) {
    if (isSuccessful) player.commitWin();
    else player.revert();
} else {
    player.restore(PlayerRules.normalizeIndex(services.stats.getTrainerIndex(), total));
}
setState((prev) => ({
    ...prev,
    currentTrainerIndex: player.index,
    totalScore: services.stats.getTotalScore()
}));
```

- `total` — число тренажёров текущей карты (длина построенной геометрии либо сумма
  `trainersCount` из `state.zones`); нормализация защищает от испорченного значения в
  хранилище.
- Повторная игра (`isReplay()`) — ранний выход: ни записи, ни синхронизации (A28/T23).
- При `false` запись в хранилище не выполняется вовсе; сообщение приходит через шину (A79).
- Тесты: победa + бросающий `repo.save` и проигрыш + бросающий `repo.save` — в обоих случаях
  `stats.currentTrainerIndex === services.stats.getTrainerIndex()`, счёт раунда не зачтён;
  успешные пути не изменились.

### T87. Контракт выхода: звук в оболочке, `useGame` молчит

```ts
// src/hooks/useGame.ts
const exit = useCallback(() => {
    depsRef.current.onExitRequested(modelRef.current!.roundScore);
}, []);

// src/App.tsx
const handleExitRequested = useCallback(
    (roundScore: number) => {
        if (exitConfirm) return;
        services.audio.play('click');
        setExitConfirm({ roundScore });
    },
    [exitConfirm, services]
);
```

- «Выйти» → `click`, закрыть, `exitGame()`, `returnToMap()` (T82); «Остаться»/оверлей →
  `click`, закрыть; состояние раунда не меняется.
- Повторный ✕ при открытой модалке — no-op целиком: ни окна, ни звука, ни записи.
- Зависимость `handleExitRequested` от `exitConfirm` допустима (идентичность меняется при
  открытии/закрытии, подписки на неё нет).
- Тесты: `App` — два ✕ → один `click` и одна модалка; `useGame` — `exit()` вызывает
  `onExitRequested(roundScore)` и не вызывает `audio.play`.

### T88. Контракт очереди сообщений в `App`

```ts
interface GameMessage {
    title: string;
    message: string;
}

const [messages, setMessages] = useState<GameMessage[]>([]);

const showError = useCallback((title: string, message: string) => {
    setMessages((prev) => [...prev, { title, message }]);
}, []);

const closeError = useCallback(() => {
    services.audio.play('click');
    setMessages((prev) => prev.slice(1));
}, [services]);
```

- Показ: `messages[0]` → `<ErrorModal title={…} message={…} onClose={closeError} />`;
  при пустом массиве модалки нет.
- Очередь не снимает больше одного сообщения за закрытие и не сортирует.
- `subscribe` остаётся один (A86); очередь наполняется и из шины, и из прямых вызовов
  `showError` (блокировка сессии).
- Тесты: (1) два `report()` → первое, после «OK» второе; (2) стартовая ошибка + `busy` →
  «Ошибка хранилища», затем «Игра уже запущена»; (3) StrictMode — без дублей.

### T89. Контракт кэша `StatsService`

```ts
_cache: Stats | null = null;

load(): Stats {
    if (this._cache) return this._cache;
    try {
        const stats = this._read();
        this._cache = stats;
        return stats;
    } catch (e) {
        this._cache = null;
        this._recover(handleError(e as Error, 'StatsService.load'));
        return this._readOrDefaults();
    }
}
```

- `_readOrDefaults()` кладёт результат в кэш (`this._cache = …`), иначе повторный `load()` после
  ошибки снова пойдёт в хранилище.
- `save(stats)`: успех → `_cache = clone(stats)`; `_reported = null`; провал → кэш не меняется.
- `_writeBack(stats)`: успех → `_cache = stats`; провал → кэш не меняется (ошибка обрабатывается
  как в A89).
- `_toMemory()` → `_cache = null` после смены репозитория.
- Геттеры (`getCurrentMap`, `getTotalScore`, `getTrainerIndex`) и `readMapState` кэш не
  инвалидируют и объект из него не мутируют.
- Тесты: одно чтение на три геттера; одно чтение на первый рендер `App` в StrictMode;
  0 чтений после `updateAfterRound`; 0 чтений после `switchMap`; провал `save` не меняет кэш;
  режим «память» сбрасывает кэш.

## 🚫 Запреты — дополнения (1.10.2)

### Z49. Запрещено в позиции и кэше

- оставлять отображаемую позицию в противоречии с хранилищем после раунда;
- менять `PlayerState` (победа/откат) до успешной записи;
- вводить второй источник позиции (`lastAttempt`, «черновой индекс», DOM-состояние);
- мутировать объект, полученный из `load()`, и хранить в кэше ссылку на объект вызывающего;
- кэшировать ошибку чтения (иначе сбой «залипает» до перезагрузки);
- вести кэш в `window.*`, `globalThis.*` или модульной переменной (A78).

### Z50. Запрещено в сообщениях и звуке

- терять сообщение в оболочке, заменять его другим или снимать больше одного за закрытие;
- фильтровать/склеивать сообщения в оболочке (дедупликация — только в источнике, A79);
- играть звук выхода вне открытия подтверждения или внутри апдейтера состояния;
- заводить второй канал показа сообщений или второй механизм подтверждения выхода (Z44/Z46);
- возвращать нативные диалоги (`alert`/`confirm`/`prompt`) — запрет 1.1.0 сохраняется.

### Z51. Запрещено в этом этапе

- новая функциональность игры (серии, бонусы, таймеры, достижения), редизайн, правка значений
  стилей и текстов существующих подсказок;
- новые рантайм-зависимости, Playwright/Puppeteer, type-aware ESLint, Prettier для `.md`;
- смена версий React/Vite/Vitest/TypeScript;
- изменение `CONFIG` (значения), формата `Stats` v3, ключей `ml_stats`/`ml_session_lock`,
  карты, звуков, текстов `ConfirmModal`;
- переписывание истории git (`rebase -i`, `reset --hard`, force-push).
